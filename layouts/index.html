Go notebooks, compiled and reactive.
Native speed, kept values, a reproducible order.

A notebook is a Markdown file whose ```go blocks are cells. The kernel compiles it into a real Go program, orders the cells by what they use — worked out from the code itself, as marimo does for Python, not from the order you ran them in — and runs only what changed. A cell whose code and inputs did not change keeps its result, and its values are handed over instead of being computed again, across rebuilds and across runs.

# Spectrum

```go
import "math"

n := 1_000_000
```

The sum below runs once; editing the last cell does not run it again.

```go
sum := 0.0

	sum += 1 / float64(i*i)
}
```

```go
math.Sqrt(6 * sum)
```

Ask it, do not take our word

The notebook above, actually run — twice.

The first run compiles the notebook and runs every cell. Why go-notebook

Speed, kept values and order — together.

Jupyter runs Python in an interpreter, with hidden mutable state, in whatever order the cells were clicked. gophernotes interprets Go. GoNB compiles, but keeps only declarations: values are computed again on every run. marimo orders cells from the code, but interprets Python. None has native speed, kept values and a reproducible order together; go-notebook is built to have all three.

📝

A notebook is Markdown

Prose is kept byte for byte (format.Parse(src).String() == src, fuzzed). GitHub shows a notebook as a document, a diff is a diff of text, and no output is ever written into the file.

⚙️

Compiled, native speed

The kernel compiles the notebook into a worker process. Go's build cache makes a rebuild after a one-cell edit cost about a tenth of a second.

🧭

Order from the code

Each cell's definitions and free identifiers come from the parse alone, so the graph works on code that does not compile yet. Cycles, double definitions and foreign assignments are errors.

♻️

Kept values

A cell's key hashes its source, the packages it refers to and the keys of the cells it reads. An unchanged key keeps its result; after a rebuild its variables are handed to the new worker. Moving cells runs nothing.

💾

On disk, across runs

Results and values are kept in the work directory, so a new kernel, or the next notebook run, starts where the last one stopped.

📄

A page with no scripts

notebook html writes a standalone page: no scripts, no external resources, raw HTML in the prose left out. A page made from someone else's notebook runs nothing of theirs.

✅

100% test coverage

Gated in CI on Linux, macOS and Windows.
